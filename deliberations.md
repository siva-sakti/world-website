## Cluster 1 — privacy & sharing (ruled → D-072)

**Findings closed:** #1 (SPEC §3 OR-leak) · #11 (boards lack a visibility field) · #13 (public-default vs morning pages).

**The core insight.** The leak came from collapsing two different questions into one OR (`on a public board OR visibility='public'`). Split them: **reachability** (*can a guest arrive at this surface?* — the board's business) vs **atom visibility** (*may this thing be seen?* — the bit's business), composed with **AND**. Board publicity never overrides bit privacy — principle 8 ("meaning travels with the bit") made literal.

**The forks and how they actually resolved:**
- **Fork A (board default) → private.** The named interaction that sold it: "bit public by default" now means *eligible once its room is published*, not *broadcast*. A locked room can't leak.
- **Fork B (private card rendering) → absent**, not a redaction placeholder — quieter, doesn't advertise that something is hidden. The record model is identical either way, so cheap to revisit at the sharing phase.
- **Fork C (contextual bit-privacy: born in a private room → born private) → DEFERRED**, and the reasoning is the valuable part: the advisor caught that **Forks A + C compose into a silent reversal of the owner's public-default ruling** — canvas-first means most bits are born on boards; boards default private; so most bits would be born private. Worse: in v1 sharing doesn't exist, so *no* board is public — the reversal would be 100%. Each fork sounded fine alone; together they reconstituted the exact default the owner had deliberately dropped. **Method lesson: judge defaults along the real creation path, never in isolation.**
- **The load-bearing detail that makes deferring Fork C safe:** the publish gate must be a **full "what a guest sees" preview** (visible *and* withheld cards), NOT a withheld-list ("3 private cards won't show — publish?"). A withheld-list only confirms *hiding* — a forgotten-*public* sensitive bit sails through unlisted; a preview catches it, because it appears. The advisor's "the review catches that case too" was true only under the preview definition — neither window had stated it. The old §2a "one-time review of everything marked public" was itself a P3 smell (a hand-maintained global pile) and is **replaced**, not supplemented.

**Sharpenings.** Board-card transitivity (publishing board A whose board-card points at public board B opens a guest path into B) is an *unexpected-path* concern, not a leak — a private board-card renders absent, so only already-public boards ever become reachable; the preview lists them. SPEC §3 is stale **twice** (the OR-leak + "everything is private by default") → authoritative on nothing privacy-related; rewritten at translation.

**Parked:** guest-pull reachability (does a guest's pull show every public bit with the tag, or only public bits on reachable boards?) → Cluster 5. Guest visibility of *vocabulary* (tag/category words on shared surfaces) → sharing phase (added at D-074).

## Cluster 2 — placement lifecycle (ruled → D-073)

**Findings closed:** #5 (board deletion unspecified) · #2 (un-place kills connectors vs P12 "reversible") · #10 (re-placement unmodeled).

**The unifying lens** — *removal is a state, not a delete; only empty-trash destroys* — was adopted for placements and boards and **rejected for connectors**. Claude's first recommendation (revive-on-replace: un-place hides connectors; re-place revives them) was overturned by two advisor arguments:

1. **It reverses §2c's own ontology.** "Old connectors are not remembered — arrows are live arrangement, not travel" places connectors with position/size (ephemeral *arrangement*), not with placements/tags (durable, timestamped *acts*). Revive-on-replace makes them remembered — quietly reopening a settled question.
2. **The zombie gap (decisive).** Un-place is not trash: the placement row persists (travel history) and the bit isn't in trash — so **empty-trash never fires for an un-placed card**, and its hidden connectors would be immortal rows with no destruction path. No clean GC rule exists because un-place has no terminal event (the card can return anytime, forever). The only clean terminal is an explicit "they're gone now" — i.e., kill-with-confirm.

**The structural tell** supporting the ruling: position and size ride the durable placement row *for free*; a connector is a *separate row* — keeping it dormant has no free home. The model itself was saying connectors don't belong in the durable category.

**The ruled connector lifecycle:** tap-delete → gone · **un-place** an endpoint card → gone, **proportional confirm only when arrows exist** (a bare card goes silently — P12 satisfied exactly) · **trash** the endpoint bit → hidden/frozen, revived on restore (D-071 #1 intact) · **empty-trash** → cascade-deleted. The undo-feel revive-on-replace was protecting survives anyway: the confirm fires *before* loss, and in-session Ctrl+Z covers the accident.

**2C precision (the tightening):** one durable placement row per (target, board), **reused** on re-place — first-arrival kept, presence back to here-now, **last departure overwritten**. "Never erased" is true of the *membership row*, not of intermediate exits; v1 is not a visit-by-visit timeline (additive later). Don't let the doc be misread as keeping one.

**2B (board deletion):** trash-is-a-freeze extended to boards — the *arrangement* freezes (placements + connectors + tag applications), board-cards pointing at it render absent, **the bits are untouched, always**; restore = exact; empty-trash cascades placements-on-it + board-cards-of-it + connectors, **never bits** (a bit orphaned of its only board = a *boardless bit* → Cluster 5); a trashed board **leaves pulls and find** (fuel for the #14 restatement); confirms proportional.

**Meta-lesson (second instance):** elegant-unification flattened a load-bearing distinction (connectors here; Fork C in Cluster 1). Every "and this one works the same way too" now gets a second look: *same kind, or exception?*

## Cluster 3 — what's a record (ruled → D-074)

**Findings closed:** #3 (content incompatibly defined) · #4 (category unlisted) · #9 (link→bookmark) · + one catch the audit missed (subtype vocabulary).

**Content.** §2b ("one field, always — auto-mirrored, a cached copy") vs §7 layer E ("a suggestion is regenerable *only until you touch it*; once edited it is your content — truth") — resolved **in §7's favor**, then followed to its end: the stored `content` holds **only owner-authored words; the machine has no write path to it** — "never silently overwritten" becomes *structural*, not promised. Display/search = the **face**, computed fresh: content ∥ per-type mechanical fallback (text: body's plain words — no mirror, the P6 worry evaporates · bookmark: captured title ∥ the URL · pdf/audio: file metadata title — ID3 etc., genuinely mechanical, no transcription · drawing/image: nothing, the visual self). Touched-vs-untouched = set-vs-empty — no flag needed; clearing your words = free revert to the fallback (**chosen**: a bookmark always shows something); §2f's evidence-gated title field turns out to be *unlocking content-writes on text bits* — the promised "one nullable column, additive" already exists — so content stays **locked for text** in v1 (writable content on text *is* a title field, and that stays behind the gate).

**The advisor's regenerability catch.** Filing "extracted title" under layer E fails P2's own test *for bookmarks*: stored truth is only the URL; the live page is external and unkept — it dies or retitles, so an *untouched* bookmark's face (the normal case) would blank or mutate on cache rebuild **with no act of the owner's** — never-silently-overwritten violated through the back door (rotting the fallback, not writing the column). **Fix, generalized as P2-applied-per-source:** *whatever cannot be rebuilt from stored truth is itself truth* → a bookmark's title is **captured once at save**, machine truth beside the URL (same species as §2a plumbing's width×height), immutable — renaming a bookmark = writing `content` (your act, your column); pdf/audio titles rebuild from layer B → stay layer E. The bookmark/pdf asymmetry is *the storage test working*, not an inconsistency to flatten. Face floor when extraction fails at save: the URL itself. Bonus: the export now preserves bookmark titles past page death.

**Eight kinds.** Category (§3b: named, mutable, holds words = stored state) + the twin: **subtype vocabulary** — §5c's "exactly like tag words" entails id-referenced stored rows (else renaming `doodle`→`sketch` edits every bit, breaking P9). Honest count = **eight record kinds, three families: things (bit · board) · acts (tag application · placement · connector) · vocabulary (tag word · category · subtype word)** — a taxonomy that *retroactively names why D-073 was right* (different families, different lifecycle rules). P9 generalized: all vocabulary renames free *by construction*. Boundary: vocabulary is never taggable, placeable, or a bit. Full "six"-sweep executed (lexicon intro/heading/table · storage map · §6a "sixth record kind" · CLAUDE.md hub · dormant "seventh"→"ninth"); the D-log kept its historical sixes (append-only). *Correction (D-077): "executed in full" was false — the soundness pass found two survivors (the lexicon's computed-surfaces intro; CLAUDE.md's terminology-norm line). Lesson: a claimed-complete sweep needs a grep, not a memory.*

**Free structural win:** `UNIQUE (tag, target)` makes tag-merge dedupe automatic (I-R7) — closing a below-the-line finding with a constraint instead of code.

**Meta-map recorded:** Claude's failure mode = *elegant-unification* (adds hidden machinery when it over-reaches); the doc's = *elegant-absolutism* (over-claimed always/nevers). The absolutism lens — "is this 'always' literally true at the record level?" — is Cluster 5's tool.

## Cluster 4 — two devices & collisions (ruled → D-075)

**Findings closed:** #6 ("last edit wins / one chair" vs the two-device premise) · #7 (the keep-by-default prompt "unbuildable" without version state).

**The reframe (the cluster's strategic core).** The auditor saw "two devices + offline outbox + last-write-wins" and read a general sync problem. But the rulings already made constrain what each device may *write*: phone = capture + browse, never compose (D-023); the outbox carries only *captures* = **births** (inserts with fresh IDs — cannot conflict with anything); the compose devices (desktop · Daylight) are online clients on one database. The whole surface = **three clash types**: referential (delete-vs-use) · edit-vs-edit · flush name-collision. This is what keeps the product a notebook instead of a sync engine.

**#7 — the prompt needs no version state.** Trash-is-a-freeze rows (Cluster 2) *are* tombstones; detection = a write/flush-time referential check (*target exists, un-trashed?*), **held on the acting device** (the failed request; or the capture stays in the outbox — flush happens with the app open, so a screen always exists to ask on); keep-by-default = restore target + land write. No vector clocks, no per-record versions, no new server state. The auditor's "unbuildable as written" was true of the *pre-hardening* SPEC (hard deletes); Clusters 2–3 had already built the needed state.

**The double correction — the mechanism was wrong twice before it became law:**
1. **Claude's claim** ("check-and-write is one statement = atomic = no race") **was wrong** — the advisor's attack succeeded: under READ COMMITTED (Postgres default, what Supabase runs), a statement checks against its start-of-statement snapshot and takes **no lock on rows it merely reads**, so a concurrent soft-delete can commit inside the statement's window and the write lands silently against a fresh tombstone. One statement closes the two-round-trip race, not the snapshot race.
2. **The advisor's fix (`SELECT … FOR KEY SHARE`) was *also* wrong, for a reason specific to this model:** key-share blocks DELETE and key-changing UPDATEs only — and a **soft-delete is a non-key UPDATE** (`SET deleted_at = …`), which takes `FOR NO KEY UPDATE` and does **not** conflict with key-share. The advisor's own supporting detail ("it's what FK checks use") was the tell: FKs guard *existence and keys*, and a tombstone is exactly the case FKs are blind to — the row still exists, merely flagged. **The ruled mechanism: `SELECT … FOR SHARE`** (the minimal lock conflicting with `FOR NO KEY UPDATE`) on the target row, in the write's transaction. The two serialized orders both resolve correctly: write-first → the delete's §3e confirm-count includes the new application; delete-first → the check hits the tombstone, the prompt fires. **Verification named:** source = Postgres's documented row-lock conflict matrix; **a two-session race probe at translation** (reproduce the silent land without the lock, show it blocked with it). Why the correction mattered: mechanism notes are followed verbatim at translation, and race bugs pass every ordinary test — a wrong lock would live forever labeled "verified."

**#6 — precise + honest.** "Last edit wins" = last write to *arrive at the database*, **whole-record** (no field merges — arrival order needs no trusted device clocks, and inserts can't be hurt by it). The false "one human in one chair" replaced with the true justification (one author, same bit rarely mid-edit on two screens; loss real, named, accepted; versioning additive — its `updated_at` already exists via P4). **The P12 boundary drawn explicitly** — the clash promise covers *referential* clashes; edit-vs-edit overwrite is outside it: the sentence that ends the #6 contradiction. (Fork 4A, optimistic concurrency, rejected: cheap to *detect*, expensive to *answer* — conflict copies + a merge UI, over-built for one author.)

**The enforcement twin (advisor's structural catch).** "No offline editing exists in any planned phase" was true but *unenforced on the compose side* — a wifi drop mid-compose plus one helpful engineering reflex (durable retry-queue) would silently reopen the general sync problem. **Ruled:** an edit reaches the database only through a live save with the owner present; nothing ever replays edits automatically; a failed compose save fails visibly and retries in memory, never durably queued. Boundary sharpened so it can't be over/under-read later: a device-local **crash-guard draft** that restores into the *editor* (human re-saves through the live path) is compatible and additive; an auto-flushing edit queue is what's forbidden.

**Corollaries ruled:** **born-at = the act's moment, never the sync's** (one-clock's offline corollary — an offline capture stamped at flush would poison recency + resurfacing, the return loop itself, with day-late lies; P4 always meant it, now it says it) · flush name-collisions attach via the **near-duplicate rule**, case-insensitive, no prompt.

**Convergence observation (advisor):** Cluster 1 reversed a fork, Cluster 2 overturned a recommendation, Cluster 3 patched one hole, Cluster 4 corrected one mechanism with the model untouched — findings shrinking toward the periphery as layers descend is what converging on a sound model looks like from inside. Cluster 4 demonstrated it twice: *both* mechanism corrections (Claude's race claim, the advisor's lock choice) left the model ruling unchanged.

## Cluster 5 — retrieval honesty (ruled → D-076) — the merge's close

**Findings closed:** #8 (the boardless bit unreachable) · #14 (the pull's "complete" not literally true) + the parked items (guest-pull reachability from Cluster 1 · the boardless orphan from Cluster 2 · trashed-boards-leave-pulls from D-073).

**#8 — the distinction that sized the fix.** The boardless bit wasn't strictly unreachable — search finds words; find-by-type finds a wordless drawing. What it lacked, precisely: the split between **lookup** (surfaces that answer when asked) and **encounter** (surfaces that show unprompted). v1 has no encounter floor — home = boards (D-070), the feed = Phase 6 *by re-blessed design* — and the worst case, the **naked bit** (no board, no tag, no words), had only find-by-type. §7's payoff ledger promised "time" as a way back v1 didn't deliver — the docs' own absolutism species. **Fix: find's empty query = the ledger** (every live bit, newest first) — zero design, zero new records, "the URL is the query" so the empty query is *everything*; home ruling untouched, the feed not smuggled in. → **I-T1**. The loose-bits filter deferred (the floor doesn't need it).

**#14 — absolute by domain, not weakened by qualifier.** Instead of "complete among live, visible bits" (honest, but a qualifier), the framing: **trash is outside the world; the pull is complete over the world, no exceptions**; restore returns a thing to the world and every pull re-includes it instantly.

**The advisor's attack (asked for, and it landed):** "outside the world" is true of *surfaces*, false of *acts* —
1. **Counts lie:** a delete-word confirm saying "3 things" while 2 frozen carriers also lose it → P12 violated by the framing itself. Fix: confirms count the frozen (*"3 things + 2 in trash"*).
2. **Merge resurrection:** merge A→B skipping frozen applications → a later restore resurrects an application pointing at deleted word A — Cluster 4's tombstone clash, *self-inflicted by a ruling instead of a race*. Fix: vocabulary ops reach every row, in-world and frozen.
Generalized in the fold, wider than the advisor took it: **every** destructive confirm reckons with the frozen — words, merges, empty-trash, board-destroy (I-T2). One rule: *the boundary governs what surfaces show, never what acts must count.*
3. **The third domain.** "Does a board contain its trashed bit?" — the world surface hides it (render rule I-L3); the history surface (ever-placed, D-071 #3) shows it, by design. **world · trash · history** — the framing wasn't wrong, it was one domain short. (Mechanism honesty kept: "nothing to rebuild" is literally true of the *pull*; the search *index* may need a reindex touch on restore — layer-E housekeeping, find only.)

**I-T1 rescoped (advisor):** acts need no surface of their own — they surface through their things; vocabulary's surfaces named (manager/picker, **count-0 words listed**). **The departed-placements flag — resolved with commitment where the advisor hedged ("name it v1 or defer it"):** the owner's **F3 rejection** rested on *"travel + accumulating pulls + revision IS growth"* (D-069), so travel stored-but-surfaceless would silently unwind an owner verdict — the one thing the merge exists to prevent. **Ruled: the bit's page shows its travel in v1** (has-been-on: board · arrived · left, read off the placement rows); the board-side "ever placed here" view deferred with a named re-entry.

**5C — "a tag opens nothing."** A guest's pull gathers only what is public AND already reachable; tags never widen reachability. The ambiguity pinned before it fossilizes: *what counts as "open"* — **globally public** (every public board; the philosophy's open-web thread + D-056 lean here) vs **share-scoped** (only what was handed over; the keyed-guest tier makes it thinkable) — a **named sub-question inside the sharing phase**; the principle survives either. Also corrected on the record: D-074's parking note had misfiled this question into the sharing phase; D-072 had parked it for this cluster — principle ruled now, feature ships with sharing.

**The merge closes.** The quality curve held to the end: Cluster 5's corrections were domain-boundary refinements; the model rulings (the framing, the floor) survived intact. **14/14 findings accounted for** — 13 ruled across D-072–D-076, #12 re-blessed (F4/F8). The model layer is done. Next per §8: the life walkthrough (scenes aimed at the wounds), then translation.

### Checkpoint A, feedback round 1 (advisor window read the full migration — verdict: approve-with-fixes)

The advisor verified the physics claims independently (twice-tagging refused · cross-board arrow unrepresentable · the face's generated-column construction · the TCM trace · all five doors) — all held. Four findings, resolved:

1. **Tour overstatement, conceded (the trust-relevant one).** The tour called `content` "physically unable to be written — no code path": wrong *frame*. The column is ordinary and owner-writable (captions are its whole job); the machine-never-writes rule and the v1 text-bit lock are **db-module discipline (I-R1's own "kept by: app"), not database physics** — the DB cannot distinguish a machine write from an owner write (same authenticated door). The agreements' "no write path" is a claim about the codebase's design, and the tour let it masquerade as a DB constraint. **Lesson: at owner checkpoints, every "the database refuses X" must name its constraint; everything else is "the code is careful," said plainly.** Corrected to the owner in-chat. *(Round 2, owner challenged the verifier — the verifier's re-check produced the definitive proof, adopted here: `bit_substance_matches_type` forbids `body` on a drawing, so a doodle's caption has nowhere to live except `content` — the schema itself proves content is owner-writable, and a builder following the tour's original prose instead of the SQL would have broken the typed-shadow feature. Port build-note: doodle/image captions are `content` writes.)*
2. **A fifth behavior-visible default routed (advisor catch — better than the two the author surfaced):** editing the *text* of bits sitting on a board (without moving anything) does NOT bump the board on home under the `greatest(board, placements)` formula. Reason it's built so: a bit lives on N boards — edit-bumping shuffles home from one edit. Advisor and author both lean **keep** (arranging is the spatial signal; the 3-week test arbitrates). ## Gather G1 — the design rationale (ruled → D-101, 2026-07-25)

**Make-then-render.** The build order is *store the fact, then show it*: G1 lays the `reference` table (the hidden plumbing) and proves it; the `[[` picker, the chip, and the "gathered into" list are rendered on top at G2/G3. Nothing visible is built before the record it stands on is proven — the same discipline as the whole translation.

**Body-as-truth, rows-derived-on-save.** A reference is never hand-authored; it is **grown from the body**. The writing is the single source of truth, the `reference` rows are its *materialized index*, reconciled on every save (add a chip → a row is born; delete a chip and save → the row falls away traceless, exactly like un-tagging). This is why "gathered into" is an instant read instead of re-scanning every note, and why it can never disagree with the body it came from — a Principle-3 surface (compute, don't maintain) even though the index is physically stored.

**The directed-vs-symmetric split — why `reference` is its own table and `dormant` still sleeps.** Gather's tie is **directed and born from a sentence** (from the writing, to the bit reached for); §6's waived pair-tie was **symmetric and hand-drawn** (two bits "relate," no direction, no writing to hang it on). They are different animals, so `reference` is a new table and the dormant table is *not* it — the direction-less, writing-less case (two doodles that belong together with no sentence between them) still has no home, so A2's re-entry stands unchanged. Collapsing the two would either force a direction onto a symmetric tie or strip gather of the writing it is born from.

**Text→text cycles are safe — but only because chips render faces, never live content.** A thought may gather a thought that gathers back; the reference graph can contain cycles, and that is fine **because a chip renders the target's *face* (a name), not its body inlined.** This is load-bearing: it is the exact reason any future "show the gathered bit's *content* inline" proposal must re-open this question — inlining live content across a cycle is non-terminating, whereas a name is a leaf. Recorded so the safety is understood, not assumed.

**Document-mode adjacency — watch, don't build.** Inline gather looks like §6b's document-mode *call-in* minus ordering and split/merge — a bit summoned into a flow of writing. It is deliberately *not* document mode: gather ties a bit *into a sentence* as a reference (an index), where document mode renders a board *as* a vertical flow with block identities, split/merge, and stored order. Gather is built format-agnostic (Markdown vs HTML deferred, parked A18) so it carries over whichever storage document mode (Plan E) eventually picks. The note exists so the two aren't conflated during either build.

**Two-device free coherence.** Because references are grown from the *winning* body on save, and the body itself resolves last-arrival-wins whole-record (§2d), the two can never disagree — the losing edit's chips aren't in the body that won, so they aren't in the index. There is nothing special to reconcile; coherence falls out of the existing rule.

**The Principle 9 carve — a knowing trade, named out loud.** A chip stores a *copy* of the gathered bit's face inside the referencing note, for one concrete payoff: **find-by-what-it-references** (Postgres can only find a note by words *in* it, so those words must be copied in). Recorded as a **trade**, not smoothed into "no-drift": it self-heals lazily (re-copies on the note's next open/save), renaming a bit rewrites nothing elsewhere, and the only cost is an untouched note showing a renamed target's old name until touched — rich surfaces always resolve live. The rejected alternative — active rename fan-out over every referencing note — would mutate notes you never touched and lie about their last-edited time (the "maintain a surface by hand" our compute-don't-maintain rule forbids); parked (A16) unless the lazy staleness genuinely annoys. Carved into agreements §1 (Principle 9) and the §6 amendment; invariant I-Ref8.

## Source made first-class; bookmark retired — the rationale (ruled → D-102, 2026-07-26)

**Why the pivot — grow thoughts, don't hoard consumption.** The founding philosophy is that you keep *notes from* what you consume, not the raw resource. A "bookmark" — a saved page kept as its own object — is hoarding consumption; it makes the notebook a place you *store pages* rather than *grow ideas*. So the reframe: a URL is not a thing you keep, it is a **source** you hang a note off. You keep the note (the quote, the thought) and remember where it came from. Retiring the bookmark object is this principle made literal. The consequence the owner consciously accepted: **there is no "saved web page (or video) as its own kept thing."** "Save this to come back to it" is not a hidden second mechanism (an auto-bookmark) — it is a **deliberate tag** (`#revisit`), the same reasoning that rejected a favorites/star (§2e): significance is a tag, never a parallel machine.

**Source clones the vocabulary family — the simpler, single-valued half.** Source is shaped exactly like `subtype_word`/`tag` (`id · name · url · created_at · updated_at`, a case-insensitive unique on `lower(name)`, owner RLS), and `bit.source_id` is `bit.subtype_word_id` verbatim (a nullable FK, `on delete set null`). It is the **simpler half** of the tag pattern: single-valued, so **no join table** (tags need `tag_application`; source doesn't — a bit has *many* tags but *one* source). This is why source earns first-class status cheaply — almost everything clones proven code, and the genuinely-new surface is bounded. It is also a real **fourth organizing axis** (source "where from" beside tags "what about", boards "where placed", dates "when"), which is *why* it deserves its own table rather than living as two frozen strings.

**Convert-before-tighten — the load-bearing ordering.** The migration order is: create `source` → migrate D-100's `source_url`/`source_title` into `source` records → **convert every `bookmark` bit into a text-note-with-source** → *only then* forbid the bookmark type. If the type CHECK were tightened before conversion, the surviving bookmark rows would violate the new rule and the whole migration would abort. The proof checks that **zero bookmark rows survive**. A bookmark converts to a text note whose body is a synthesized rich-text link (`<a href="url">title-or-url</a>`) because a text bit requires a non-null body — the conversion synthesizes one rather than leaving a hole.

**The name-fallback — a title-fetch can fail.** `source.name` is NOT NULL, but a clip whose page-title never loaded (an auth-walled Drive/Instagram URL) has only a link. So the created source is **named after its link**: `name = coalesce(source_title, url)`. Nothing is ever blank, nothing is lost. This is the same reality the S1 retreat scene names (captured-title fetch fails on auth-walled URLs), now handled at the record level.

**Two deliberate small losses, named.** The `captured_title` column is now unused on live rows (a harmless leftover, cleaned up later; I-R3 moot, the I-R2 `bookmark:` face branch dead-but-harmless — no function edit). And a bookmark that carried a *preview picture* loses that picture's link on conversion (the file becomes an orphan in storage, tidied later) — a converted note is a **link**, not a picture. Neither loses any of the owner's own words.

**The A14 re-home.** A14 (video as a stored type) previously read "video = a *reference* (bookmark to Drive/YouTube)." With the bookmark object gone, that mechanism is gone — so a video is now a **source on a note**, or a **rich-text link inside** a note, not a saved object. The re-entry condition is unchanged: the day a video wants to be a placeable/taggable *bit* (or a linked video dies and it hurts), a `video` type is additive with the same two-halves storage as images.

**Standing.** Proven on a throwaway copy of the real database (the full proven chain applied in filename order, then the exact data this change must convert seeded, then the migration applied and a suite run green), then applied to cloud with the owner's conscious sign-off. This reverses parts of D-100 (its two `source_*` columns) and supersedes `capture-build-plan.md` (→ `old/`). A want-driven pivot the owner ruled in knowingly, in the same family as D-087/D-101 (owner authority, recorded as such).

## Notes as synthesis surfaces + the hard line (D-118 → D-121, 2026-08-25 → 08-28)

**The rulings:** notes are first-class written pieces (D-118/D-119) · the bit/note division + two-way placement (D-120) · the **hard line — a thing never changes type** (D-121). Built: N1 (a note's own writing page, `/note/[id]`), N2 (the `board-surface.tsx` breakdown that cleared the way), N3 (a note on a board = a page-shaped doorway).

**The core insight — the synthesis framing.** The model resolves to one move: *take scattered material and bring it together into something you can take forward.* Everything is either **material** (bits) or a **surface where you synthesize** (notes, boards). A note and a board are the *same kind of thing* — a place you bring material together — differing only in **how**: a note stitches it *in words* (verbal), a board *in space* (spatial). This is the owner's framing, held consistently since the N1 correction; the doc work was catching up to it.

**What a bit is — role, not size.** A bit is *material*: raw input you bring into a synthesis, **any size**. The owner's own catch: "a PDF is finished, but it's still a bit." So a bit is defined by its role (input), **not** by being small — someone else's whole finished PDF is *your* material. → "bits are small things" was retired for **"bits are the material."**

**The hard line (D-121) + what was rejected.**
- **Rejected: the fluid promote/demote toggle** (D-118/D-119 shipped a "make a note" / "note ✓" button that flipped a saved thing's `kind`). Owner: if a thing freely converts between bit and note, the two names stop meaning anything. Ruled out — `kind` is fixed at birth; the toggle + `setBitKind` were removed (I-K1).
- **Rejected: a "start a note from this bit" button** (Claude proposed it as a bridge). It is *not* the flip — it makes a *new* note and leaves the bit, so it doesn't break the rule — but it was declined for now: to write a piece from bits you **write a note and gather them in** (`[[`), which already exists. No new machinery.
- **The "note is like a PDF" catch.** The owner said this to convey the *finished feeling* on a board, not a taxonomy. Claude over-read it into a "document family" (note + PDF as a class distinct from bits) — **rejected**: PDF and voice memos are **bits**. A note is a **surface** (peer of a board), full stop.

**Storage stays shared (deliberate).** A note is a `bit` row with `kind='note'` — invisible plumbing, so notes inherit tags/find/trash/gather/export. The hard line lives at the *concept/UI* level, not storage. (Three layers allowed to differ: model = surface · storage = a bit row · presentation = a surface.)

**Meta-note — Claude's failure mode, named by the owner ("it feels like I keep losing you").** The owner's core was *stable and clear the whole time*; the breakdowns were Claude's, in a specific pattern: **over-formalizing a simple idea** (inventing the document family, the escape-hatch button) and **over-rotating on the owner's most-recent analogy** instead of holding the through-line. Same elegant-unification bias flagged in Cluster 3's meta-map — *watch for added hidden machinery.* Fix: hold the stable core; treat the owner's analogies as *feeling*, not taxonomy; ask "structure or feeling?" before building on one. ## Archive — proposed, audited, and sent back (2026-08-28 → D-122)

**What was wanted (owner, in their words):** *"the possibility for archiving and deletion for anything that is a unit in our app whether that's a bit or board or a note."* Something you're done with should stop being in the way without being thrown away.

**What was built before any of this was ruled — the process failure first, because it caused the design failure.** A single multiple-choice question ("is archive its own state, or is trash enough?") went straight to a migration and a UI. The word **"put away" was invented in a button label.** It reached a UI, a SQL comment and two plan docs without ever being ruled. The owner's reaction — *"'put away' feels like an unclear phrase. and in general i am confused why this isnt as clear as it could be"* — was correct: it was unclear because nobody had decided it. This produced the loop's new **step 2b** (name it before you build) and a check at step 8.

**The model proposed** (and now rejected as written): every unit is in one of three states — *live* (in your rooms) · *archived* (put away, still findable in search) · *trashed*. Two act-pairs move between them. Three rules: trash outranks archive; archived stays findable; nothing is both starred and archived.

**Two independent audits ran against the code.** What they found, most serious first:

1. **"Rooms" is not a word in this model, and it contradicts a locked invariant.** `lexicon.md` defines **world** as the pull · find · home · boards · the graph, and **I-T4** locks *three surface domains, no fourth*. An archived row is a live row, so it is **in the world** — i.e. in all five. "Out of the rooms" silently invented a fourth domain. Rule 2 patched one of the five surfaces (find) and left four unruled. This is the root cause of the implementation gap, not a separate bug: not knowing what the concept *was*, the build filtered `archived_at` in one query (`/notes`) out of the six that list bits.
2. **Cascade cannot follow the trash precedent, and the trap is sharp.** Trashing a board makes its bits **loose** — the ruled guaranteed way-back (§7 / `the_inbox`). Archive a 200-card board and follow that rule: 200 bits land in the loose pile, so a tidying act produces the messiest possible result and archive becomes *worse than trash* for reachability, inverting rule 1. Don't follow it: those bits are on no reachable board and in no inbox, reachable only through find — and the inbox's ruled promise quietly stops covering them. **Proposed resolution (not yet ruled):** archive never cascades and never changes looseness; a third location is named in the lexicon — a bit is *on a board* · *loose* · **or on a put-away board**. If that third location is not acceptable, archive should not extend to containers at all.
3. **The two act-pairs are not symmetric, though the model presents them as such.** `restoreBit` touches only `deleted_at`, so trash→restore preserves the star. Archive **clears `pinned_at` permanently** and un-archive does not return it, with nothing recording it existed. Rule 1's promise ("restoring returns a thing to what it was") is kept by one pair and broken by the other. **Proposed resolution:** suspend rather than destroy, or say plainly in the rule that the star is lost and make the act confirm it — a tooltip is not consent.
4. **Rule 1 is false for `updated_at`.** The `bit_updated_at` trigger fires on every update including archive/trash, and `/notes` orders by `updated_at`. Taking an old piece back out lands it at the **top** of the notes room, above yesterday's writing.
5. **Acts drag archived things back into rooms without unarchiving them.** Every act door guards `deleted_at` and ignores `archived_at`: an archived note can be called onto a board, offered by the `[[` picker, and placed from its own page. The state stops describing anything. **Proposed resolution:** *using a thing revives it* — placing, calling in, or gathering clears `archived_at`. Self-repairing rather than self-contradicting.
6. **A gather chip renders an archived bit's content inline inside a live note.** Not merely findable — displayed, in a room. No listing filter can fix this; it needs a ruling.
7. **The archive has no room of its own.** Its only listing is `/notes?archived=1`, scoped to `kind='note'` — so an archived image or doodle has **no listing surface at all** (an I-T1 reachability breach the moment archive extends past notes, which the model says it does). That listing offers *trash* but not *take-back-out*: the destructive act is one click, the restorative one is not. And `trash_listing` carries no archived marker, so restoring a thing archived in June and trashed in July makes it vanish — correct per rule 1, and unlearnable.
8. **The universal quantifier is simply false.** `shelf_group`, `tag` and `source` have neither `deleted_at` nor `archived_at`; folders are **hard-deleted**. Vocabulary is deliberately carved out of the trash promise (§ agreements), but **folders are not vocabulary** — they are arrangement, closer to boards. Either name them a fourth thing exempt from states and say why, or re-examine the carve-out.

**What held.** State completeness: all six reachable flag combinations map onto three named states with none unnamed, and the CHECK is correctly a disjunction at the lowest layer. Find deliberately not filtering archive is right — the one thing rule 2 actually demands. Trash-outranks-archive is correctly implemented for the field it was written about.

**Ruling: sent back to step 2b.** The migration is written and throwaway-proven (8/8, `verification/archive-proofs.sql`) and is **not applied to any cloud**; the UI is reverted off the working branch. Nothing is wasted and nothing shipped. Archive re-enters as its own loop when the owner answers the three questions the audits isolated — see `parked.md`.

**The lesson, separate from archive:** every defect above lives in the **verbs**, not the nouns. The schema is sound; what was undocumented was *what happens when you do a thing*. That is the case for `units-and-actions.md`, and it is evidence rather than preference.
